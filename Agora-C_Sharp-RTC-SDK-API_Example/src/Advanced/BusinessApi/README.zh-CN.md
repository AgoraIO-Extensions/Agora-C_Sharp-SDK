# 独立 Windows C# 业务场景 Demo

继续使用 FULL 包。仍是原来的 Demo、同一个 EXE、同一个主窗口；原有七个示例保留。新场景直接位于主窗口标签栏，不另开调试窗口，不需要选择任意 API 或手工拼参数。

## 通用操作

1. 主窗口左侧填写 AppId、频道。右侧顶部填写本轮 RTC Token、本地 UID、远端 UID和单频道角色。
2. 点右侧“初始化”可先测试设备、播放器和录音；左侧“joinChannel”会初始化并加入当前单频道，“leaveChannel”退出但保留业务引擎以观察退出回调。需要结束本轮时点右侧“释放”。
3. 在六个业务场景之间切换不会退出当前通话，播放器ID和Token等也保留。切回原来的七个示例会释放业务引擎，避免多引擎抢占设备。双频道合唱使用页面中的A/B进退按钮，左侧单频道按钮在该页暂停使用。
4. 每个按钮有业务含义；选择设备/文件/用户后直接操作。同步返回、ref查询值和真实异步回调分开显示；进退频道、播放器状态、播放位置和接收消息还会更新页面结果。
5. “导出日志”保存当前有界日志。事件拥塞/容量截断会有提示，必要时分轮测试、分轮导出。不会用SDK返回0自动认定业务验收通过。

## 双端与合唱示例

- A、B两个进程使用不同的本地UID，远端UID填写对方。单频道可按SDK语义使用0自动分配；双连接场景要求明确的非0 UID，以免回调与Token身份不明确。
- 先在主唱进程选择伴奏文件，点“开始主唱示例”。页面会分别展示打开请求、播放器就绪、等待入会、提交播放等阶段；只有收到对应连接的入会回调才播放。仍需观察播放器真实状态，并在另一进程确认伴奏和麦克风声音。
- 手工验证时可在播放器场景创建/打开/播放，在合唱场景选角色并勾选“发布所选播放器的伴奏”，对A/B分别加入或更新媒体选项。顶部播放器ID在各场景共用。
- 进度同步通过消息场景的“填播放器进度消息”生成，选择实际连接后发送；接收端核对内容、NTP、播放位置和端到端现象。这不是替业务实现所有网络抖动/时延补偿算法。
- “停止并退出合唱”取消待开始流程、停止PCM，停止/销毁本轮主唱示例播放器（或手工所选播放器），分别请求退出A/B。其余手工创建播放器可继续在播放器场景管理；全部结束时释放引擎。

## 验收边界

- 当前版本音频元数据是技术预览，发送与接收长度须匹配，范围1～255字节；文本按UTF8字节数计算。错误长度/空缓冲区等在派发前保护，不能把面板拦截当作SDK错误返回。
- 曲库需要独立资质/Token；FULL包也不能替代业务服务鉴权。授权信息不写入命令日志。曲库、metadata和废弃日志Setter不作为稳定支持承诺，保留实际返回/回调。
- 自定义音轨须在入会前创建，发布时填写真实trackId；DIRECT轨道应关闭麦克风发布。PCM区域用20ms UI计时器发送，不能用作硬实时/合唱漂移指标验收。
- Windows音频设备枚举返回DeviceInfo数组，设备数量/名称/ID直接显示；不使用旧集合getCount或错误的视频设备查询。移动端SetEnableSpeakerphone不在Windows场景中调用。
- 原业务表中的云端合流、服务端接口、IM和歌词业务逻辑仍需对应业务环境；不是补一个SDK按钮就能宣称方案已通过。
- 离线检查验证参数、缓冲区和自动主唱流程的时序/身份保护。Windows CI会打开原主窗口的六个真实场景，检查按钮绑定及入参，逐页渲染截图，并验证x86/x64包启动。真机设备、双端通话、播放器和合唱效果另由QA验收。

## 跨频道转发（Ex 连接）

1. 源连接先使用直播频道场景、主播角色加入，等待入会成功。A 取左侧 ChannelId/顶部 UID，B 取“连接B频道/B UID”；A/B 是本机连接编号，不是实际频道名。
2. “转发源连接”选实际已加入的 A 或 B。填写独立“源转发Token”：启用证书时按实际源频道、UID=0生成，不使用本地入会 UID/Token。
3. 填不同于源频道的目标频道、目标 UID 及匹配的目标转发 Token；目标 UID 不得与目标频道已有用户冲突。未启用证书时 Token 按项目配置可留空。
4. 点击“开始/更新转发”，使用 StartOrUpdateChannelMediaRelayEx(configuration, sourceConnection)。观察 OnChannelMediaRelayStateChanged 和目标端声音；返回0仅说明请求被接受。功能须已开通。
5. 更新时保持同一源连接，修改目标配置后再次点击。切源前先停止；“停止转发”使用启动时捕获的源连接，不随输入框变化。停止成功后仍需检查回调；释放引擎会清除本地绑定。

日志案例：实际加入 business-b/1100122，却以123/1001作为源并向123转发，普通转发接口返回-8。现改用可选源Ex连接，源转发UID固定0并分离鉴权，防止再次形成同源同目标配置。实际服务鉴权和双端音频仍须Windows真机验收。

## SDK 日志路径与等级

在初始化前到“曲库与诊断”选择日志文件（父目录须存在且可写）、等级和大小，再点击顶部“初始化”。配置通过 RtcEngineContext.logConfig 传入；路径留空使用SDK默认目录，Windows通常为 `%LOCALAPPDATA%/Agora/<process_name>/agorasdk.log`。默认INFO，大小128–20480 KiB；NONE明确关闭日志。

已初始化时，编辑输入框不会自动生效：可释放后重新初始化，或点击对应旧版设置按钮验证 SetLogFile/SetLogLevel/SetLogFileSize；旧接口不补写初始化前日志。内部DEBUG/API_CALL不再出现在下拉框。QA日志中的level=32是内部DEBUG，底层转为filter=0，两个198字节文件正好停在该切换处；SetLogFile本身返回0，不能据此判定路径设置失败。修改后实际落盘内容仍需Windows重测，收集SDK轮转日志、agora-iris.log及Demo导出记录，而不是只取一个文件。

## NMS-31857：角色、设备音量、耳返及中文显示

- **单频道角色**：直播场景下，在顶部选择主播/观众后点击旁边“应用单频道角色”；仅改变下拉框不调用SDK。已在单频道内时提交角色和发布选项更新，观察 OnClientRoleChanged / OnClientRoleChangeFailed 及对端声音；入会前只预设角色。双连接仍使用合唱页的角色及A/B媒体更新按钮。主播恢复发布时尊重“发送本地音频”选项。
- **设备音量**：先初始化，刷新麦克风/扬声器，界面按SDK当前设备ID选择，不默认把第一项当作当前设备。选择设备后填0–255音量并点击“设置所选设备音量”：先切换到所选设备再设置，随后读回当前设备ID和音量。“查询当前设备音量”只查询，不切换。界面显示请求/实际读回差异；硬件量化、驱动、系统跟随及实际声音须另行核对。与下方0–400采集/播放信号增益区分。
- **耳返**：连接耳机，勾选耳返、填0–400音量，点击“应用耳返”；依次请求开启本地采集、耳返并设置音量。仅设置音量不会隐式开启耳返。关闭时取消勾选并应用；释放清除本地请求状态。返回0只表示接口请求成功，没有可用耳返音量getter，不虚构“实际读回”；需检查采集/设备回调、SDK日志及本机实际声音。原“无声”是否涉及当前Windows Native实现或设备限制仍须现场复测。
- **中文接收**：回调展示按Unicode显示中文，保留UTF-8字节长度、十六进制和合法JSON转义；继续隐藏Token/AppId及签名URL查询参数。截图中的\u56DE\u9B42是“回魂”的JSON转义，不代表UTF-8字节丢失。

建议依次复测直播频道内主播/观众往返切换、麦克风/扬声器最小/中间/最大音量及切换设备、耳返0/100/400及关闭重开、中文混合ASCII/换行/引号消息；不能以离线契约/按钮检查代替双端设备验收。

## 独立 C# 曲库中文回调闪退修复

Iris 4.5.3.6-build.8（551d0b68）事件数据为UTF-8，data_size为字节数。Windows ANSI/CP936解码含中文歌曲及嵌套JSON字符串时可能吞掉转义反斜线，造成解析失败；旧解析辅助方法返回空对象后，生成分发读取requestId触发KeyNotFoundException并越过Native回调边界。

修复仅位于手写MusicContentCenterEventHandlerNative入口：独立C#按原生指针及data_size显式解码UTF-8，再交给原生成分发；Unity原有分发路径保留。坏编码/JSON、缺字段及业务回调异常只输出事件类型/异常类型诊断，不输出响应正文和签名URL，不补造requestId，也不把失败记为成功。

回归通过原生内存结构投递未转义的中文JSON，覆盖7162848780338400及“爱人错过/告五人”、NUL计数兼容、缺requestId、非法UTF-8/JSON、回调异常及下一次恢复；Windows CI在x86/x64均运行同一测试。此前仅以完整转义后的托管JSON测试，未覆盖真实Windows字节解码。实际曲库服务查询仍须使用项目有权访问的歌曲ID和匹配曲库Token，不应把默认1视为有效歌曲；现场闪退与播放效果仍需使用新签名包复测。

## 4.5.3.8 新增接口验收

本 Demo 继续使用原主窗口的六个业务场景，接口目录增加到 129 个类型化重载。

- 曲库页：初始化曲库并注册事件，在“供应商确认的曲库扩展请求 JSON”中填写业务服务提供的请求（顶层包含 vendorId），点击“发送曲库扩展请求”。检查 SendExtRequest 的返回值和输出 requestId，再检查 OnExtResponse 的 requestId、httpCode、选项和响应。返回 0 仅表示请求已提交，不能代替异步业务结果。vendorId 1 为 YJX，2 为 TME；具体 action/参数须使用供应商约定，Demo 不伪造请求模板。
- 音频设备页：初始化后选择回环源类别 1（音频输出）、2（运行应用）或 3（两者），点击“枚举回环录音源”，在结果中核对应用名、窗口标题及进程 ID 列表。枚举本身不会开始录音。
- 填入逗号分隔的排除应用名或进程 ID，点击“创建回环（关闭旧采集）”，记录返回的音轨 ID。Demo 根据实际数组长度设置计数；Windows 仅首个排除项生效，进程 ID 优先于应用名，应用名包含 .exe。不要把 0–255 设备音量与音轨音量混淆。
- 使用“发布回环音轨”“取消回环发布”“设置回环发布音量”及“销毁回环音轨”检查返回结果；枚举/创建成功不代表已经发布。释放引擎时会清理本页创建的音轨。

SDK 新增 GetLoopbackRecordingSources 返回托管快照数组；Iris 已复制并释放原生列表，调用方不应再释放列表指针。LoopbackAudioTrackConfig 增加 excludedAppNames/excludedAppCount、excludedProcessIds/excludedProcessCount；直接使用 SDK 时应保持计数与数组一致。保留原五参数构造函数；OnExtResponse 为可选虚方法，旧的曲库监听器不必新增实现。

旧的 GetMusicCharts、GetMusicCollectionByMusicChartId、SearchMusic、GetLyric、GetSongSimpleInfo 按 4.5.3.8 原生头文件标记为弃用且仅支持 YJX，现有入口仍保留。新版曲库实际鉴权、供应商响应和真实设备回环音效由 QA 验收。曲库中文回调修复及异常边界继续保留。

### NMS-31857 补充复测

耳返步骤：初始化 → 在音频设备页选择耳返滤波类型 → 勾选耳返 → 点击“应用耳返” → 设置音量。下拉项来自 SDK 的 EAR_MONITORING_FILTER_TYPE；Demo 将所选枚举值原样传入，不写死 0 或 NONE。启用时依次恢复音频模块、开启本地采集、提交耳返及音量；关闭时只关闭耳返。请求失败会保留 SDK 错误，不继续设置音量或宣称已启用。请用真实耳机逐项验证可听效果、关闭/重开和释放重建。

数据流与音频元数据接收区直接显示解析后的 UTF-8 正文，另列连接、发送 UID、字节数和 HEX；不以 JSON 字符串转义形式代替正文。测试中英文、单/双引号、反斜杠、加号、尖括号、换行与制表符，并核对发送与接收 HEX。诊断日志仍保留 JSON 格式与凭据隐藏，日志中的 JSON 转义不能视为传输字节改变。

### NMS-31888 系统回环与排除规则

新回环的排除规则不会修改旧 EnableLoopbackRecording 的采集配置。两个入口现已串联互斥：创建新音轨会关闭旧采集；切回旧采集会先取消新音轨发布并销毁。系统声音采集不需要创建 MediaPlayer。

1. 初始化、加入频道，并应用主播角色。测试时使用耳机，先关闭麦克风上行以区分麦克风声学回授和系统回环本身的声音。
2. 音频设备页选择回环源枚举类别并枚举，确认目标应用的真实进程 ID。类别 1/2/3 只影响枚举结果，不改变采集或发布模式。
3. 填排除 PID/应用名，点击“创建回环（关闭旧采集）”。检查旧采集=false、新音轨 ID 已返回。Windows 只使用首个排除项，PID 优先于应用名；修改排除项后需重新创建。
4. 点击“发布回环音轨”，检查返回值及“发布请求=true”。此步骤只设置所选回环音轨的发布标记和 ID 列表，不修改麦克风或播放器发布选项。未入会/观众不能提交发布。
5. 以音量100为基线：播放被排除的 QQ 音乐，远端应不收到该应用；再播放未排除应用，远端应收到正常声音。分别记录采集端/远端日志、PID、设备和录音。高于100的增益可能导致削波，不能用高增益噪声直接判断排除功能。
6. “取消回环发布”只取消当前音轨；“销毁回环音轨”会先取消发布再销毁。重复创建会先清理旧音轨。操作失败保留可重试状态，连接重连过程中不假定旧发布已消失。
7. 切回播放器页勾选“旧系统采集（无排除规则）”并应用，会停止新音轨后启用旧路径。检查状态和实际声音；退出/释放后重建回归。

此次修复确认了 Demo 流程缺口，不等于已证实 Native 杂音根因。若上述单一路径、音量100、耳机/关闭麦克风条件下仍有杂音，请附录音及双方 SDK/Iris 日志继续定位。
